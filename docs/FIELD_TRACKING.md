# Trackium Core field map and independent routing

From **Settings → Open independent field map**, create/edit a plan with latitude, longitude in travel order, 2–10 lines. Tap **Calculate road preview**, review the destination that will receive your planned stops, and explicitly calculate. The resulting passenger-car preview shows graph, OSM snapshot, estimate and active road geometry. **Save and activate road locally** persists the selected geometry and plan in Android Keystore-backed storage. **Select saved local road** changes the active route among up to five stored results per map. Plans and previews work without any Gateway sign-in. Provider failure preserves the active local route.

From **Devices → Open device observation** after existing owner-approved native pairing, the separately scoped map combines authorized AOVX location and individual fixes with its own local road. Create or copy the intended waypoints into that device's plan. While the screen is foreground and unlocked, it rechecks the observation source every 15 seconds when idle. Manual refresh is also available. UTC measurement and Gateway receipt are separate. Historical samples remain discrete. Rings denote buffered history; the current marker comes from the eligible position projection. Distance to an active road uses a recent eligible fix, is advisory, and never mutates Cargo or proofs. [Core pairing and phone checks](PHONE_ACCEPTANCE.md)

Use **Import offline OSM road GeoJSON** for regional linework. The bounded local format is a WGS84 GeoJSON FeatureCollection with 1–1,000 LineString features, at most 20,000 points total and at most 1 MiB. Import legally authorized ODbL data with its attribution. Pinch/drag or use Zoom and Fit. The map reads local linework and never requests remote tiles. No observations, history, Minima data, credentials from another service, or implied progress are sent to the provider. An uncalculated plan displays stops only.

## Provision a routing provider independently

On an operator-controlled host, run a Valhalla 3.6.3 attestor with a verified graph on a private Docker network. The Trackium graph artifact supplies the original config and attestor, which exposes status and route on port 8002 and engine loopback port 8003. The independent deployment uses a different origin and different credentials from the Railway–Oracle mTLS bridge. Preserve that bridge as deployed. [Pinned engine and graph preparation](https://github.com/themightydanik/trackium/blob/main/docs/valhalla-b1/README.md)

A [standalone Nginx example](examples/core-valhalla.nginx.conf) authenticates Core at exactly POST /route. Use a locally operated instance that can resolve Docker service name `valhalla`. Use the reviewed Nginx image `nginx:1.28-alpine@sha256:a8b39bd9cf0f83869a2162827a0caf6137ddf759d50a171451b335cecc87d236`, one worker, an unprivileged UID, read-only mounts and a writable temporary directory. Expose only its approved TLS port 8443 to authorized devices. Mount the SSL full chain as `/pki/server.crt`, key as `/pki/server.key` and a password-file mount as `/pki/users`. The certificate must be trusted by the target Android and valid for the origin name. Use approved network controls and a dedicated route-only account. For an existing unused password path, `umask 077; htpasswd -cB /secure/core-routing/users owner` prompts for a password. Choose a 32–64-character random ASCII password, and keep credentials out of shell args, logs and commits. Use Nginx restricted mount permissions for its container UID. The example drops the auth header before contacting the attestor and logs no route request data.

Under **Configure independent road provider**, enter the operator HTTPS origin (including the port if applicable), route-only username/password and exact graph release ID. Normal TLS trust and hostname checks apply. Core accepts no cleartext URL, redirects, alternate endpoint paths, non-JSON responses, mismatched graph/version or broken geometry. The response must include `X-Trackium-Graph-Id`, `X-Trackium-Engine-Version: 3.6.3`, `X-Trackium-OSM-Snapshot` and a Valhalla polyline6 trip in kilometers, one leg per pair of consecutive stops. The app sends only the draft stops after confirmation. Deployment and Android pairing at an actual independent host require the owner's authorization.

The disposable JVM integration test may be run with `TRACKIUM_FIELD_TEST_CA` pointing to the disposable localhost test CA. It uses the pinned Lviv–Rzeszów graph behind the example Nginx config on loopback port 8443 and fixture-only credentials. Production never imports that CA.
