# Field observations in Trackium Core

Use **Devices → Open device observation** after owner-approved native Gateway pairing. The optional pairing works with an authorized HTTPS Gateway, including a self-hosted deployment. Core startup and local Minima remain independent. Resolve access for the intended tracker and tenant on the owner machine using the existing [phone acceptance procedure](PHONE_ACCEPTANCE.md). A Lite company login cannot authorize a native session.

The native device detail plots the current physical location projection and up to 20 recent observations already authorized for that device. Portray the larger colored dot as the last-known fix and a ring as buffered history. The plot leaves the space between individual reports undrawn. Device UTC, Gateway receipt, provenance and stale status stay separate. Tap **Refresh tracker observation** while parked or as a passenger to revalidate the session and update the plot. An absent eligible fix stays unavailable. The underlying measurements remain unverified AOVX observations.

Use **Edit local waypoint plan** to create or edit 2–10 stops, one decimal latitude/longitude pair per line in travel order. The plan is encrypted locally and scoped to the configured origin, tenant and device. Dashed segments connect planning points on the coordinate plot. The plot requests no map tiles, uploads no locations and infers no movement between device reports. Independent road calculation and road deviation still need an approved Core provider/authentication contract. The current B2/B3 customer workspace requires a Lite customer session, whereas native pairing grants separate rights.
